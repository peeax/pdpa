# เลขที่เรื่อง ๖/๒๕๖๘

## เรื่อง

สำนักงานคณะกรรมการดิจิทัลเพื่อเศรษฐกิจและสังคมแห่งชาติ และสำนักงานปลัดกระทรวงสาธารณสุข หารือเกี่ยวกับการจัดทำข้อตกลงการประมวลผลข้อมูลส่วนบุคคล (Data Processing Agreement: DPA) ภายใต้โครงการพัฒนาระบบคลาวด์กลางด้านสาธารณสุขของประเทศไทย

---

## ข้อกฎหมายที่เกี่ยวข้อง

### ๑. พระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. ๒๕๖๒
- มาตรา ๕ วรรคหนึ่ง
- มาตรา ๖
- มาตรา ๓๗ (๑) และ (๔)
- มาตรา ๔๐ วรรคหนึ่ง วรรคสอง และวรรคสาม

### ๒. พระราชบัญญัติการจัดซื้อจัดจ้างและการบริหารพัสดุภาครัฐ พ.ศ. ๒๕๖๐

### ๓. ประกาศคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล เรื่อง มาตรการรักษาความมั่นคงปลอดภัยของผู้ควบคุมข้อมูลส่วนบุคคล พ.ศ. ๒๕๖๕
- ข้อ ๖

### ๔. ประกาศคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล เรื่อง หลักเกณฑ์และวิธีการในการแจ้งเหตุการละเมิดข้อมูลส่วนบุคคล พ.ศ. ๒๕๖๕
- ข้อ ๘

### ๕. มติคณะรัฐมนตรี
- วันที่ ๒๔ มกราคม ๒๕๖๖
- เรื่อง ขออนุมัติก่อหนี้ผูกพันข้ามปีงบประมาณเพื่อดำเนินโครงการพัฒนาระบบคลาวด์กลางด้านสาธารณสุขของประเทศไทย พ.ศ. ๒๕๖๖–๒๕๖๘ และอนุมัติงบประมาณรายจ่ายประจำปีงบประมาณ พ.ศ. ๒๕๖๖

---

## ข้อหารือ

### บริบท

สำนักงานคณะกรรมการดิจิทัลเพื่อเศรษฐกิจและสังคมแห่งชาติ (สดช.) และสำนักงานปลัดกระทรวงสาธารณสุข (สป.สธ.) หารือเกี่ยวกับสถานะของผู้ควบคุมข้อมูลส่วนบุคคล (Data Controller) และผู้ประมวลผลข้อมูลส่วนบุคคล (Data Processor) ภายใต้โครงการพัฒนาระบบคลาวด์กลางด้านสาธารณสุขของประเทศไทย ซึ่งมีการทำบันทึกข้อตกลงความร่วมมือ (MOU) ระหว่างกระทรวงดิจิทัลเพื่อเศรษฐกิจและสังคมกับกระทรวงสาธารณสุข และมีการว่าจ้างกิจการค้าร่วม A พัฒนาระบบคลาวด์

### ประเด็นคำถาม

#### ๑. สถานะของ สดช.
สดช. ซึ่งทำหน้าที่บริหารโครงการและว่าจ้างกิจการค้าร่วม A มีสถานะเป็นผู้ประมวลผลข้อมูลส่วนบุคคลหรือไม่

#### ๒. การจัดทำ Data Processing Agreement (DPA)
หาก สดช. ไม่เป็นผู้ประมวลผลข้อมูลส่วนบุคคล จะสามารถลงนามใน Data Processing Agreement (DPA) ได้หรือไม่ และมีบทบาทหน้าที่อย่างไร

#### ๓. การจัดทำ DPA ระหว่าง สป.สธ. กับกิจการค้าร่วม A
สป.สธ. สามารถทำ DPA กับกิจการค้าร่วม A ได้โดยตรงหรือไม่ แม้จะไม่มีนิติสัมพันธ์ในฐานะคู่สัญญาตามกฎหมายจัดซื้อจัดจ้าง

## ประเด็นข้อหารือที่ ๑
### สถานะของ สดช.

คณะอนุกรรมการเห็นว่า การพิจารณาว่าองค์กรใดเป็นผู้ควบคุมข้อมูลส่วนบุคคลหรือผู้ประมวลผลข้อมูลส่วนบุคคล ต้องพิจารณาจากข้อเท็จจริงในการดำเนินงาน ไม่ใช่เพียงข้อความในสัญญาหรือ MOU โดยพิจารณาจากผู้ที่มีอำนาจกำหนด

- วัตถุประสงค์ (Purposes)
- วิธีการ (Means)

ในการเก็บรวบรวม ใช้ หรือเปิดเผยข้อมูลส่วนบุคคล

### สป.สธ. มีฐานะเป็นผู้ควบคุมข้อมูลส่วนบุคคล (Data Controller)

เนื่องจาก

- กำหนดชุดข้อมูลและมาตรฐานข้อมูล
- กำหนดสิทธิการเข้าถึงข้อมูล
- กำหนดแนวทางด้านความมั่นคงปลอดภัย
- มีบทบาทในการกำหนด TOR และตรวจรับโครงการ

### สดช. มีฐานะเป็นผู้ประมวลผลข้อมูลส่วนบุคคล (Data Processor)

เนื่องจาก

- พัฒนาและให้บริการระบบคลาวด์ตามคำสั่งของ สป.สธ.
- ไม่มีอำนาจกำหนดวัตถุประสงค์หรือวิธีการประมวลผลข้อมูล
- ไม่มีสิทธิเข้าถึงข้อมูลโดยอิสระ
- ต้องปฏิบัติตามคำสั่งของ สป.สธ.

หาก สดช. ว่าจ้างบุคคลอื่นดำเนินการแทน บุคคลดังกล่าวจะมีฐานะเป็น **Sub-Processor** และ สดช. ต้องรับผิดชอบต่อการดำเนินงานของ Sub-Processor ต่อ สป.สธ.

อย่างไรก็ตาม หากข้อเท็จจริงปรากฏว่า สดช. ไม่ได้ประมวลผลข้อมูลเลย และมีเพียงผู้รับจ้างดำเนินการแทนโดยตรง หน่วยงานสามารถปรับ MOU และกำหนดให้ผู้รับจ้างเป็น Data Processor ของ สป.สธ. โดยตรงได้

นอกจากนี้ หาก สดช. ใช้ข้อมูลเพื่อปฏิบัติหน้าที่ตามกฎหมายของตนเอง ไม่ใช่ตามคำสั่งของ สป.สธ. สดช. จะมีฐานะเป็นผู้ควบคุมข้อมูลส่วนบุคคลสำหรับการดำเนินการนั้น

---

## ประเด็นข้อหารือที่ ๒
### การจัดทำ Data Processing Agreement (DPA)

เมื่อ สดช. มีฐานะเป็น Data Processor

สป.สธ. มีหน้าที่ต้องจัดทำ DPA กับ สดช. ตามมาตรา ๔๐ วรรคสาม

แม้ สดช. จะทำหน้าที่บริหารโครงการหรือบริหารสัญญา ก็ยังสามารถลงนามใน DPA ได้ เพราะบทบาทดังกล่าวไม่ใช่อำนาจกำหนดวัตถุประสงค์ในการประมวลผลข้อมูล

แต่หากมีข้อสรุปร่วมกันว่า สดช. ไม่ใช่ Data Processor และผู้รับจ้างเป็น Data Processor โดยตรง

สป.สธ. สามารถทำ DPA กับผู้รับจ้างโดยตรงได้ และไม่มีหน้าที่ต้องทำ DPA กับ สดช.

หาก สดช. ประสงค์จะร่วมลงนาม ก็สามารถลงนามได้ โดยต้องสอดคล้องกับบทบาท หน้าที่ และ MOU ที่เกี่ยวข้อง

### ข้อสังเกตเพิ่มเติม

DPA ควรกำหนดให้ผู้ประมวลผลข้อมูล

- มีมาตรการรักษาความมั่นคงปลอดภัยของข้อมูล
- แจ้งเหตุละเมิดข้อมูลส่วนบุคคลแก่ผู้ควบคุมข้อมูลภายใน ๗๒ ชั่วโมง
- ปฏิบัติตามมาตรา ๓๗ และมาตรา ๔๐ ของ พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล

---

## ประเด็นข้อหารือที่ ๓
### การจัดทำ DPA ระหว่าง สป.สธ. กับกิจการค้าร่วม A

แม้ สป.สธ. จะไม่ได้เป็นคู่สัญญาตามกฎหมายจัดซื้อจัดจ้างกับกิจการค้าร่วม A แต่หากข้อเท็จจริงปรากฏว่า

- สป.สธ. เป็นผู้ควบคุมข้อมูลส่วนบุคคล
- กิจการค้าร่วม A ประมวลผลข้อมูลตามคำสั่งของ สป.สธ.

ย่อมถือว่ามีความสัมพันธ์ระหว่าง Data Controller กับ Data Processor ตาม พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล

ดังนั้น

สป.สธ. ต้องจัดทำ DPA กับกิจการค้าร่วม A เพื่อควบคุมการประมวลผลข้อมูลให้เป็นไปตามกฎหมาย

การดำเนินการสามารถทำได้ ๒ แนวทาง

1. สป.สธ. ทำ DPA กับกิจการค้าร่วม A โดยตรง

2. หาก สดช. เป็น Data Processor
   - สป.สธ. ทำ DPA กับ สดช.
   - สดช. ทำ DPA กับกิจการค้าร่วม A ในฐานะ Sub-Processor ตามเงื่อนไขที่ สป.สธ. กำหนด

ทั้งนี้ ให้เป็นไปตามความเหมาะสมและข้อตกลงร่วมกันของทุกฝ่าย

## สรุปผลการวินิจฉัย

### ๑. สถานะของคู่กรณี

- สป.สธ. เป็นผู้ควบคุมข้อมูลส่วนบุคคล (Data Controller)
- สดช. เป็นผู้ประมวลผลข้อมูลส่วนบุคคล (Data Processor) หากดำเนินการตามคำสั่งของ สป.สธ.
- ผู้รับจ้างที่ได้รับมอบหมายจาก สดช. มีฐานะเป็น Sub-Processor

### ๒. การจัดทำ DPA

- หาก สดช. เป็น Data Processor ต้องจัดทำ DPA ระหว่าง สป.สธ. กับ สดช.
- หากผู้รับจ้างเป็น Data Processor โดยตรง สป.สธ. สามารถทำ DPA กับผู้รับจ้างได้

### ๓. การทำ DPA กับกิจการค้าร่วม A

แม้ไม่มีนิติสัมพันธ์ตามกฎหมายจัดซื้อจัดจ้าง แต่หากมีความสัมพันธ์ระหว่าง Data Controller กับ Data Processor ตามข้อเท็จจริง ก็ต้องจัดทำ DPA เพื่อให้เป็นไปตามมาตรา ๔๐ แห่ง พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล

## ข้อเสนอแนะเพิ่มเติม

### ๑. พิจารณาสถานะจากข้อเท็จจริง
กำหนดสถานะของ Data Controller และ Data Processor จากอำนาจในการกำหนดวัตถุประสงค์และวิธีการประมวลผลข้อมูล ไม่ใช่เพียงข้อความใน MOU หรือสัญญา

### ๒. จัดทำ DPA ให้สอดคล้องกับบทบาทของแต่ละฝ่าย
กำหนดหน้าที่ ความรับผิดชอบ มาตรการรักษาความมั่นคงปลอดภัย และการแจ้งเหตุละเมิดข้อมูลส่วนบุคคลให้ชัดเจน

### ๓. กำกับดูแล Sub-Processor
หากมีการว่าจ้างผู้ประมวลผลช่วง ต้องกำหนดเงื่อนไขการควบคุมให้สอดคล้องกับมาตรา ๔๐ และผู้ประมวลผลหลักต้องรับผิดชอบต่อการดำเนินงานของผู้ประมวลผลช่วง

### ๔. ทบทวน MOU และสัญญาที่เกี่ยวข้อง
เพื่อให้สอดคล้องกับบทบาทตามกฎหมายคุ้มครองข้อมูลส่วนบุคคลและลดความเสี่ยงในการตีความสถานะของแต่ละหน่วยงาน
